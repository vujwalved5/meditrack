## 4. SHARED COMPONENTS TO CREATE (before fixing screens)

Build these once and reuse. Put them in the project's components folder with matching naming style.

### 4.1 `formatEnum(value)` helper

Converts a machine string to human text.

| Input | Output |
|---|---|
| `needs_attention` | `Needs attention` |
| `in_use` | `In use` |
| `out_of_service` | `Out of service` |
| `available` | `Available` |
| `` (empty) / null / undefined | `—` |
| `already Fine` | `already Fine` (unchanged if no underscores) |

Rule: replace `_` and `-` with a space, lowercase everything, then uppercase only the first character.
Place in a utils file. **Use it everywhere an enum/status/state is rendered** (search for each place found by the grep in 2.2).

### 4.2 `<StatusBadge status="…" />`

Props: `status` one of `available | in_use | maintenance | out_of_service | overdue | inactive | active`, optional `label` override.

Visual spec (every property is required):

- `display:inline-flex; align-items:center; gap:6px;`
- `padding: 4px 10px; border-radius: var(--radius-pill);`
- `font-size:12px; font-weight:500; line-height:16px; white-space:nowrap;`
- Left dot: `6px × 6px` circle, `background: var(--st-…-dot)`.
- Background / text colour from tokens:

| status | label | colours |
|---|---|---|
| `available` | Available | available |
| `in_use` | In use | inuse |
| `maintenance` | Maintenance | attention |
| `out_of_service` | Out of service | critical |
| `overdue` | Overdue | critical |
| `inactive` | Inactive | **neutral (grey, NOT red)** |
| `active` | Active | available |

- **No border** (or a 1px border at 20% of the dot colour — pick one and use it for every badge).
- The badge text is ONLY the status label. Extra info like "Bed 7" is **never** inside the badge (see P0-01).
- Accessibility: the dot is decorative (`aria-hidden="true"`); the text carries the meaning.

### 4.3 `<Button variant="primary|secondary|ghost|danger-text" size="md|sm">`

- `md` height **40px**, `sm` height 32px; padding `0 16px`; `border-radius: var(--radius-sm)`; `font:600 14px`.
- `primary`: `background var(--brand-600); color #fff;` hover: darker by ~8%.
- `secondary`: `background var(--surface); border:1px solid var(--line); color var(--ink-900);` hover: `background var(--surface-2)`.
- `ghost`: transparent, hover `var(--surface-2)`.
- `danger-text`: transparent, `color var(--st-critical-fg)`, hover bg `var(--st-critical-bg)`.
- Icon + label: `gap 8px`, icon 16px.
- Focus: `box-shadow: var(--focus-ring); outline: none;` (use `:focus-visible`).
- Disabled: `opacity .5; cursor:not-allowed`.
- Transition: `background, box-shadow var(--t-fast) var(--ease)`.

### 4.4 `<Icon>` consistency

Pick ONE icon family (use the one already installed; if lucide is installed use lucide). **Remove all emoji used as icons** (the Morning Brief header uses an emoji). Icon sizes: 16px inline, 20px in headers; `stroke-width: 1.75`; colour inherits `currentColor`.

### 4.5 `<Tooltip>` / `title`

Create a simple accessible tooltip (or reuse an existing library). Must show on **hover and keyboard focus**, and be dismissible with `Esc`. Use `role="tooltip"` and `aria-describedby`.

### 4.6 `<ConfirmDialog>`

Modal with title, body text, Cancel (secondary) and Confirm (primary or danger). Requirements: focus is trapped inside; `Esc` cancels; focus returns to the trigger on close; backdrop click cancels; Confirm button receives initial focus **except** for destructive actions where Cancel receives initial focus.

### 4.7 `<Card>`

`background var(--surface); border:1px solid var(--line); border-radius: var(--radius-md); box-shadow: var(--shadow-1);` default padding `var(--space-5)`.

### P0-07 · Morning Brief contains a factually wrong sentence and a date mismatch

- **Seen on:** Morning Brief text: *"availability stands at 39 items out of 61 in use"* (39 is the **available** count; 22 are in use). Title says **October 4, 2026**, footer says **Generated 05 Oct**.
- **Cause:** LLM free-text output is not validated.
- **Fix (backend/prompt layer — do all three):**
  1. **Compute all numbers in code**, not in the LLM. Build a structured object `{ total, available, in_use, maintenance, out_of_service, checkouts_yesterday, utilization_yesterday_pct, overnight_count, overdue_count, pending_requests, report_date, covers_date }` and pass it to the prompt as JSON.
  2. **Prompt rule:** "Use the numbers exactly as given. Never recompute. Output a `summary` of at most 2 sentences (max 45 words) and no bullet list."
  3. **Post-generation validator:** extract every integer/percentage from the LLM `summary`; every number must exist among the structured values (allow ±0 tolerance). If validation fails → regenerate **once**; if it fails again → use this deterministic fallback template (and log a warning):
     `"{available} of {total} items are available and {in_use} are in use. {overnight_count} items have been checked out overnight."`
- **Fix (UI layer):**
  - Title: `Operations brief · {weekday}, {D Month YYYY}` where the date is the **generation date** (05 Oct 2026), and if the brief covers a different day, show a caption: `Covers 4 Oct 2026`.
  - Remove the bullet list that repeats the paragraph (see P1-11 for the final Morning Brief layout).
- **Acceptance:** the sentence "39 items out of 61 in use" can no longer appear; the card never shows a date that contradicts "Generated …".
- **Test (automated):** unit-test the validator with (a) a summary containing the wrong sentence (`"39 out of 61 in use"` when `in_use=22`) → expect failure/fallback; (b) a correct summary → pass; (c) a summary with an invented number (`"12 items"`) → fail.
